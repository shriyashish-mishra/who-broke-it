How it works

The repo carries its own engineering context. Any agent that can run a shell command can play, and Claude Code is proven end to end.

    The Engineering Graph

    Goal → requirements → tasks → contracts → agents → commits → PRs, as plain files in your repo. This is a real plan, generated by wbi plan for a SaaS app. Click a task. Or break a contract.

    Break a contract:

    Click a task to trace what it depends on (blue) and what depends on it (red). Break a contract to see its blast radius. We'll tell you who to apologise to.

    Many agents, one repository

    Each agent works in its own isolated worktree on its own task branch. They declare intent before touching code, and wbi checks the declaration against everyone else.

    Two laptops. One task. Git decides.

    No server, no account. Teammates on separate machines share state through the git remote you already have. A push to a ref is an atomic compare-and-swap, so exactly one claim wins.

    The agent says it's done.

    "Done" is a claim. The Agent Judge checks it against scope, contracts, your constitution, tests and acceptance criteria. Risky changes (migrations, security, public API) wait for a human. Criteria only a person can sign are never attested by an agent.

    ⚖Objection: the agent says it's done.

    What's proven, and what isn't

    Open-source tools lie by omission. Here is the whole truth.

    ✓ Verified

    • Claude Code run end to end over MCP and the CLI protocol. It found five real problems we then fixed.
    • Linux, macOS and Windows CI, including a 24-process database stress test.
    • Sync raced on a real GitHub repo: exactly one claim wins, every time we tried.
    • The merge gate on real pull requests, installable via curl, Homebrew and go install.
    • Every transcript on this page is captured from a real run.

    ◌ Integration targets (not run)

    • Codex CLI, Gemini CLI, Cursor, OpenCode, Aider. The adapter architecture supports them, and the files follow their docs, but nobody has run those agents through wbi yet. Help verify one →
    • GitLab, Bitbucket and self-hosted git for sync: untested.
    • Linear and Jira sync: not built (generic webhooks are).
    • Authorized teammates are trusted with each other: signatures stop outsiders and forgery, not insiders.

    Install it in 30 seconds

    curl -fsSL https://raw.githubusercontent.com/shriyashish-mishra/who-broke-it/main/install.sh | sh

    Verifies the SHA-256 checksum and refuses to install on a mismatch.

    brew install shriyashish-mishra/tap/wbi
    go install github.com/shriyashish-mishra/who-broke-it/cmd/wbi@latest

    Needs Go 1.26+.

    Download wbi_<version>_windows_amd64.zip from the latest release, unzip, and put wbi.exe on your PATH. Windows is covered by CI tests; the demo scripts are bash.
